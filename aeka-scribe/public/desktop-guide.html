Aeka Scribe: Setup and Feature Status

This guide sets out how to install and configure Aeka Scribe, the voice dictation and meeting notes workspace for the web and Windows, and records the status and limits of each feature in this release.

Build status: Source checks, 120 automated tests, the web build and the desktop interface build passed for 0.6.0. The Windows installer has not yet been rebuilt and signed for this release. Windows execution, real microphone/ system audio, cursor insertion, calendar consent and paid AI calls still need a Windows smoke test. This is a development release.

1. Getting started on Windows

  1. Download the Windows ZIP supplied with this workspace. The NSIS installer installs Aeka Scribe for all users of the computer and asks for administrator approval; use it on managed devices. Alternatively, extract the entire ZIP folder to a location you control (a per-user copy), then open Aeka Scribe.exe. Keep its resource files beside it. Windows 10/ 11 x64 is required.
  2. Open Desktop setup and add your OpenAI API key. The key is encrypted for your Windows account; do not paste it into a chat or note. API usage is billed to your own provider account.
  3. Choose your microphone and language under Settings. Make a short dictation in Aeka Scribe first. Then focus a normal text field in another application and use Ctrl+Shift+Space to start and finish.
  4. Automatic insertion checks the original foreground window and the focused field. If focus changes, a password field is detected, or Windows blocks access, use Copy. Your previous clipboard is restored if it was not changed in the meantime.
  5. For a meeting, open Meetings, confirm that participants know you are recording, and choose microphone plus system audio or microphone only. Start, pause, resume and finish from the recording controls.
  6. Completed audio chunks are saved before transcription. Keep Aeka Scribe open to process pending audio. If the device is offline or no API key is configured, the queue remains on this device. For offline transcription, configure a trusted whisper.cpp executable and ggml model, select Local Whisper and save preferences. Models and binaries are not bundled.

Upgrading from an earlier release: On first launch, Aeka Scribe automatically copies app data from an earlier Flow Desktop installation. New backups use the .aekabackup extension; .flowbackup files from earlier releases can still be imported. The policy file location is set out under Administration and updates.

Closing the main window keeps Aeka Scribe in the system tray. Use the tray to reopen or quit. A normal Quit offers to finish an active recording before closing. Forced termination still cannot flush unsaved audio: a power failure or forced termination may lose the current unsaved chunk (up to approximately 20 seconds), and previously saved chunks are recovered on restart. Windows policies may block the bundled PowerShell helper. Aeka Scribe reports that failure; do not disable organisation security controls.

3. Calendars

The ChatGPT Google Calendar plugin and the independent Windows executable use separate connections. A connected ChatGPT plugin does not give this executable account credentials. To connect Google Calendar or Outlook:

  1. Register an OAuth client you control. For Google, enable the Calendar API, configure consent/ testing users and create a Desktop app client. For Microsoft, register a public desktop application with supported account types, read-only delegated Calendar access, and a Mobile and desktop application redirect of http://localhost/callback. The app chooses a local ephemeral port.
  2. In Desktop settings, expand Calendar app registration. Save the provider's client ID. If Google's desktop registration provides a client secret, save that too. Do not use a web-app client or an unrelated secret.
  3. Choose Connect and complete sign-in and consent in your system browser. Aeka Scribe uses PKCE and a short-lived local callback. Calendar access is read-only by default. Optional email-read, email-send and calendar-write permissions are requested only after you select them under Email, collaboration & CRM and reconnect.
  4. Refresh Meetings. The app reads the next 14 days from the primary Google calendar or default Outlook calendar, up to 250 events per account. A failed refresh keeps prior events with an error message. Disconnect removes local access and refresh tokens. Revoke the grant in your provider account to remove provider-side consent as well.

Joining a call opens its supported HTTPS meeting link. Your browser or calling application handles login, admission, microphone and camera access. Aeka Scribe does not bypass call login and does not join as a meeting bot. Reviewed calendar workflows can separately create events and send invitations after explicit confirmation.

Meeting automation: Refresh your calendar, choose a meeting under Schedule a recording, confirm participant notification and select system audio, optional call-link opening and a stop grace period. Keep Aeka Scribe open and Windows unlocked. A visible countdown offers Cancel. Stale calendars, missed starts and overlapping recordings are skipped. Extend a running scheduled recording by 15 minutes when needed. A cancelled or interrupted start is never silently retried.

Document context: Open a saved note, then Meeting toolkit, then Attached context. PDF and Word text is parsed locally. Original files/ images are not stored. The attached text follows note sync, sharing and retention.

Automatic briefs: In Desktop settings, enable the schedule and choose a local hour, a 12/ 24/ 48-hour lookahead and a daily limit of 5/ 10/ 20. One eligible meeting with invitees or a call link is prepared per minute after that hour, using prior related saved notes. New notes go into your chosen folder. Keep Aeka Scribe running, Windows awake, calendar access fresh and OpenAI configured. After sleep or shutdown, only future meetings are considered. The schedule does not automatically join calls, read email, send messages or run while the machine is off. Failed/ interrupted generations require an explicit retry.

Semantic search: Explicitly build/ refresh the local index, then enable it. OpenAI text-embedding-3-small produces encrypted local vectors; each question is embedded and semantic matches are combined with keywords inside your chosen scope. New/ edited notes require a refresh. Trash, deleted notes and active recordings are excluded; changed/ deleted notes lose their old vectors. Index content is limited to the first 6,000 characters per note. Indexing and questions incur API usage; the index is not backed up or synced.

7. Storage and recovery

Native notes, profile, tokens and saved meeting audio are encrypted in the local Windows user-data directory of Aeka Scribe. A random vault key is wrapped by Windows DPAPI through Electron safeStorage. If another Windows account cannot unlock the key, the app does not silently replace it.

Portable snapshots use a separate password and authenticated encryption, and are saved with the .aekabackup extension. They include notes, templates/ recipes, dictation profile and preferences, but exclude API keys, calendar tokens and audio. Imports preserve conflicting notes as separate copies. Keep your password; it cannot be recovered. Manually saving a snapshot to a synced folder replaces the previous snapshot, so use your cloud provider's version history or dated exports for backups. Manual snapshots do not propagate deletions.

Continuous sync: Open Desktop settings, opt in to copying notes to your web account, then choose Connect account & enable sync. Sign in through the separate sandboxed web window and close it. Aeka Scribe uses the existing sign-in of the hosted site, not an embedded service token. It pins the first account to this vault and refuses a different account. Notes, folders, summaries and transcripts sync; raw audio, history, API keys and calendar tokens do not. Conflicts are retained as separate notes. Recording/ pending-audio notes wait. Web note pages refresh every 15 seconds while visible. Continuous sync propagates deletions; a local edit to a deleted note becomes a separate conflict copy. Independent backups are unaffected. If embedded sign-in is rejected, sync remains disconnected and local capture still works; there is no authentication bypass.

Browser dictation profile/ history remains in browser storage. Hosted scratchpads/ meeting text are saved under your authenticated site identity. Browser meeting audio waits locally in IndexedDB and is removed after successful transcription. Clearing browser data can erase pending audio. Raw audio is not stored in the hosted database.

8. Models

The default speech model is gpt-transcribe. Speaker-separated audio import uses gpt-4o-transcribe-diarize. Summaries, Ask and text transformations default to gpt-4.1-mini, configurable in the native app. Speech recognition and text rewriting are distinct steps. Compare representative Indian English, Hindi/ code-switching, names, amounts and negation before choosing a model for production use.

9. Administration and updates

Policies: Hosted sharing and cloud-AI controls are enforced on server requests. Hosted note retention runs on access, up to 100 expired notes per request; local note retention runs while Aeka Scribe is open. Active recordings and pending native audio are protected. The audit stores event metadata only, up to 1,000 events per owner (the latest 200 are shown). It is not an immutable compliance archive.

Administrators can install the supplied Admin/policy.example.json at %ProgramData%\Aeka Scribe\policy.json with administrator-only write permissions. A policy file at the earlier location, %ProgramData%\Flow Desktop\policy.json, is still honoured as a fallback. Aeka Scribe finds the ProgramData folder from the machine registry rather than the %ProgramData% environment variable, which users can change. The policy can also pin the update publisher with updateFeed, updatePublicKey and updateThumbprint; set all three or none. Use the per-machine installer on managed devices, because a user can modify a ZIP copy.

Updates: Publisher setup accepts only a public release-signing key, HTTPS feed and Windows publisher certificate thumbprint. A compatible, unexpired signed manifest, an exact byte count/ hash and a valid Windows publisher signature are all required. When your administrator pins the publisher, Publisher setup shows Managed by your administrator and cannot be changed. Otherwise, Windows asks you to confirm the feed host and publisher thumbprint before they are trusted. Optional automatic downloads check every six hours and keep an installer already verified for the same release. Installation requires a click and a Windows confirmation showing the version and publisher, and waits for recordings/ transcription to finish. No production signing certificate or feed is included, and the delivered unsigned build cannot pass this production update check. See Admin/ADMIN-SETUP.txt.

10. Windows verification checklist

  1. Confirm launch, tray reopen and quit. Confirm shortcuts register and releasing the hold-to-talk key (F8 by default) stops recording.
  2. Dictate the reported test phrase "hello, how is the weather today?" once and confirm that a single final sentence results. Repeat a word deliberately and confirm it remains.
  3. Check insertion in Notepad, Word and Outlook. Change focus during dictation and confirm automatic insertion is refused. Check password and elevated fields. Confirm clipboard restoration.
  4. Record microphone only, then a test call with headphones and system audio. Pause/ resume, unplug the microphone, and reconnect.
  5. Disconnect the network, record two chunks, restart Aeka Scribe, reconnect and retry. Confirm each chunk appears once and no unsaved recording is falsely shown as complete.
  6. Connect each calendar using your client registrations; verify event time zone, refresh, reminders, meeting link and disconnect.
  7. Generate a summary, Ask and a transform with your configured key. Check amounts, names, decisions and cited notes.
  8. Enable sync with a test note, edit it on web/ desktop, test a concurrent conflict and deletion, then disconnect. Confirm another signed-in account is refused.
  9. Schedule and cancel a test recording, check the countdown and stop/ extend controls, and verify that missed/ locked/ overlapping starts are skipped.
  10. With separately authorised site access, verify viewer/ editor permissions, comments, revocation, expiry and team dictionary import. Do not use real sensitive notes for the first test.
  11. Select your trusted local Whisper executable/ model, transcribe offline and compare names/ amounts against cloud output.
  12. Export an encrypted snapshot and import it into another Windows account/ device. Verify password rejection and conflict copies. Keep an ordinary dated backup before relying on sync-folder snapshots.

Automated verification: 120 automated tests pass. They cover permission separation, frozen review payloads, duplicate and uncertain sends, provider response contracts, scheduler idempotence/ concurrent edits, document safety and semantic scope isolation. PDF and DOCX extraction and the reviewed-send interface were checked with local test fixtures; those fixtures are not included in the release. No live messages, invitations, CRM notes or paid AI requests were sent during testing.

Reliability: The fix for repeated dictation text remains covered by a regression test. Queue processing can be awaited safely during retries, note completion handles concurrent transcription updates, and dictation profiles retain their version marker. Unversioned native profiles from release 0.2 migrate on load.

The 120 automated checks exercise sync/ deletion conflicts, account pinning, sharing authorisation, retention, automation cancellation/ recovery, update integrity/ publisher checks, profile migration and provider contracts with mock responses, encryption integrity, OAuth state rejection, transcript retry idempotence, final-frame flushing, user isolation and conflict handling. They do not establish microphone accuracy, hosted visitor consent or live provider connectivity.
